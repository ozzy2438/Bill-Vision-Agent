# Data sources and attribution

## FATURA v2

- Authors: **Mahmoud Limam, Marwa Dhiaf, Yousri Kessentini**, Digital Research Center of Sfax.
- Title: *FATURA Dataset*, v2 record, DOI **10.5281/zenodo.10371464**.
- Official record: https://zenodo.org/records/10371464
- License: **CC BY 4.0**, https://creativecommons.org/licenses/by/4.0/
- Official archive: https://zenodo.org/api/records/10371464/files/FATURA2.zip/content
- Archive name: `FATURA2.zip`; size **690,717,658 bytes** (approximately 658.72 MiB).
- Published checksum: `md5:4c9404462f22c5241eb1a290a02eb2a2`.
- Synthetic dataset: 10,000 invoice identities across 50 templates. White and colored versions are the same business cases, not 20,000 independent cases.

The preparation command selects 25 different templates, one invoice per template, with deterministic seed 42 and one background per identity. Original JPEGs are unchanged. Annotations are copied unchanged to the separate ignored `reference_annotations/fatura_v2/` directory. The runtime never opens that directory or sends its contents to the model. Only uploaded file OCR enters extraction; no filenames, sample-to-order mappings or annotation answers enter the model prompt.

`data/fatura/selection.json` records selected identities, hashes and provenance. The default command uses official HTTPS byte ranges to avoid downloading the entire ZIP. ZIP member CRCs are checked and local SHA-256 hashes are recorded; **the full archive MD5 is not claimed verified in selective mode**. `--archive` and `--download-all` verify the published full-archive checksum. Archive, selection images and labels are excluded from Git.

```bash
uv run python -m scripts.prepare_fatura --count 25
# Or after downloading the official archive locally:
uv run python -m scripts.prepare_fatura --archive /path/to/FATURA2.zip --count 25
# Optional complete archive download (size above):
uv run python -m scripts.prepare_fatura --download-all /path/to/FATURA2.zip
```

The original annotation directory is used only by preparation for JSON validation and copying. No invoice amount or supplier label is copied into demo company records. This selection is for exploring documents, not a measured extraction benchmark.

## Independent synthetic company and demonstrations

`data/suppliers.csv`, `data/purchase_orders.csv`, `policy.yaml`, `policy.md` and `data/demo/*.pdf` are original, entirely fictional demo fixtures, licensed **CC0 1.0**: https://creativecommons.org/publicdomain/zero/1.0/ . They do not represent FATURA's actual business relationships or real customers. The `DEMO-TAX-001` tax identifier is deliberately fictional.

The A/B PDFs are generated by `scripts.prepare_demo`, not taken from FATURA. A is 2,000 AUD; B is 2,200 AUD; both compare with an independently seeded 2,000 AUD tax-inclusive order. C uploads A's identical bytes. The extraction runtime still reads these PDFs through Docling/Tesseract and the local model; it has no prepared-answer shortcut.

No CORD or DocILE data is used.
